Before you start

Prerequisites

  • 1
    Claude Code CLI installed Install from claude.ai/code or run npm i -g @anthropic-ai/claude-code in your terminal. Requires an Anthropic account.
  • 2
    Git (or ZIP download — see step 1) Git is used by claude skills install to pull the repo automatically. If you don't have Git, you can download a ZIP instead — instructions in step 1 below. To check: open Terminal and type git --version. If it's not installed, macOS will prompt you to install Xcode Command Line Tools — click Install and wait ~2 minutes.
  • 3
    Chrome or Edge browser Required for the feedback widget's per-slide review feature. Firefox works for presenting but cannot save the review file locally. Safari is not supported for review.
Installation

Get up and running in 3 steps

1

Install the Claude skill

Run this in your terminal. It pulls the full decktools repo into ~/claude/decktools and registers the skill globally in Claude Code.

claude skills install github.com/mtoolin-sf/sf-decktools

No Git? Use the ZIP instead

Download the repo as a ZIP from GitHub, unzip it to ~/claude/decktools, then run claude skills install ~/claude/decktools pointing at the local folder. Claude Code will register it the same way.

2

Open Claude Code in the decktools folder

All deck files live here. When the skill is active, Claude automatically reads the brand rules and component library from this folder — you never have to describe the system yourself.

cd ~/claude/decktools && claude

You can also open Claude Code from your applications launcher and use /cd or open a new session pointed at the folder from the Claude Code UI.

3

Preview the canonical example

Before building anything, open sf-composer.html directly in Chrome — it's a fully rendered 12-slide reference deck showing every component, animation, and copy pattern. No server needed; just open the file.

open ~/claude/decktools/sf-composer.html

On Windows: right-click the file in Explorer and choose Open with Chrome.

4

Build your first deck

Back in Claude Code, run the skill. It loads every brand rule automatically, then asks you a set of questions to scaffold the full deck.

/decktools new

Claude will ask: customer name, their primary color, story arc, two or three KPI numbers, and the use cases to feature. Answer those — it builds the full HTML file.

Day to day

Two core workflows

Building a new customer deck

  1. Open Claude Code in ~/claude/decktools
  2. Run /decktools new
  3. Answer 6 questions (Claude handles the rest)
  4. Open the generated HTML file in Chrome — no build step
  5. Iterate with plain English: "make the hero copy more direct"
  6. Share the file or host it — it's self-contained

Editing an existing deck

  1. Open Claude Code in ~/claude/decktools
  2. Say: "edit mybrand.html — change the proof section"
  3. Claude loads all style rules automatically before touching the file
  4. Review the change in Chrome, iterate
Async review

The feedback widget

How it works — reviewer side

Every deck built with decktools has a floating review button (bottom-right). Share the deck URL with a teammate — they open it in Chrome and leave comments directly on each slide. No Slack thread of disconnected feedback. No screen share required.

1
Click the chat icon bottom-right to open the review panel
2
Enter your name once — it's remembered for the session
3
Navigate slides, type comments — each one is tagged to the slide automatically
4
On first comment, Chrome asks permission to save feedback.md to your local folder — grant it once
5
Click "End Review" — saves the final file and shows a summary

Applying feedback — author side

After the reviewer sends you their feedback.md, drop it in the decktools directory and tell Claude:

read feedback.md and apply the changes to mybrand.html

Claude reads the per-slide comment threads and applies each change — copy edits, layout changes, and design notes — then reports back what it did.

Presenter mode: click the screen/play icon (in the slide controls) to hide the review widget entirely during a live demo. Click again to restore review mode.

Staying current

Updates

Auto-update prompts

When the decktools skill is updated, Claude will tell you at the start of your next session:

Your deck, your responsibility

Hosting & ownership

Decktools gives you the design system and the skill — it does not host your decks. Every deck you build is yours to own, deploy, and share.

How it works

When you run /decktools new, Claude creates a repo under your GitHub account and pushes the HTML there. The decktools repo (mtoolin-sf/sf-decktools) is never touched — it's the source of the skill and design system only. Your deck repos are completely separate.

Hosting your deck

The easiest option is GitHub Pages — it's free and serves the HTML instantly:

  1. Go to your deck repo on GitHub → Settings → Pages
  2. Source: Deploy from a branch, branch: main, folder: / (root)
  3. GitHub gives you a public URL within ~60 seconds

Your responsibility

Once pushed to your repo, you are responsible for the content, access controls, and any customer data in the deck. Set your repo to private if the deck contains confidential information, and share the GitHub Pages link only with intended recipients. Decktools has no visibility into your deck repos and cannot access or modify them.

The mtoolin-sf/sf-decktools repo is read-only for all users. Nobody outside the maintainer can push to it — your install is a local clone on your own machine.

Presentation craft

The methodology behind the structure

SF Decktools enforces a narrative structure — not just a visual one. The section order (Why Now → Gap → Solution → Proof → Roadmap) is built on two well-tested frameworks used by the world's best enterprise presenters.

Tell — Show — Tell

The single most important demo technique in B2B sales. Audiences don't absorb what they see — they absorb what they're told to look for.

  1. Tell — frame the problem and set the expectation before showing anything
  2. Show — demonstrate the solution in the customer's specific context
  3. Tell — reinforce what they just saw and connect it back to the stated problem

Further reading: Storylane — Tell Show Tell · Demostack Glossary

Bowden Persuasion Blueprint

Michelle Bowden's framework — used by Salesforce teams globally — structures every presentation around audience analysis, message design, and deliberate delivery. Her Persuasive Presentation Skills Masterclass is the most widely attended program of its kind in Australia.

Key principle: your opening must establish the cost of doing nothing before you show the solution. Decktools enforces this in the Why Now and Gap sections.

Official course: michellebowden.com.au · Book: How to Present (Wiley)

How it maps to your deck: the Why Now slide is your first Tell — it frames the urgency. The Gap slide deepens the tension. Your product demo or use case slides are the Show. Proof and Roadmap are your closing Tell — evidence that the solution delivers, and a path forward the customer can own.
