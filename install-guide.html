What you get

Three things that work together

Design System

Tokens, components, fonts, icons, and brand rules — all correct, all ready. Drop them into any deck with two `<link>` tags.

Claude Skill

Run /decktools new — Claude asks you 6 questions (customer, use cases, KPIs, colors) and builds the full deck. It reads every brand rule automatically so you never have to brief it on the design system.

Feedback Widget

Every deck ships with an async review widget. Reviewers leave comments per slide — like Google Slides — and Claude reads the output to apply changes automatically.

Installation

Get up and running in 4 steps

1

Install the Claude skill

Run this in your terminal. It pulls the full decktools repo into ~/claude/decktools and registers the skill globally in Claude Code.

claude skills install github.com/mtoolin_sfemu/decktools
2

Open Claude Code in the decktools folder

All deck files live here. When the skill is active, Claude automatically reads the brand rules and component library from this folder — you never have to describe the system yourself.

cd ~/claude/decktools && claude
3

Preview the canonical example

Before building anything, open sf-composer.html directly in Chrome — it's a fully rendered 12-slide reference deck showing every component, animation, and copy pattern. No server needed; just open the file.

open ~/claude/decktools/sf-composer.html

On Windows: right-click the file in Explorer and choose Open with Chrome.

4

Build your first deck

Back in Claude Code, run the skill. Claude interviews you and builds the full deck from your answers.

/decktools new

Claude will ask which narrative mode you want — pick based on how much prep time you have:

Quick Just the basics

Customer name, primary colour, 2–3 use cases, and a few KPI numbers. Claude fills the rest from Salesforce best practices. Good for a first draft or a same-day ask.

Full Tell — Show — Tell

Claude walks you through the full narrative arc: the customer's pain point, what doing nothing costs them, the solution in their context, and proof. Deck sections map directly to Tell → Show → Tell so the story lands in the room.

Deep Bowden Persuasion Framework

The full Michelle Bowden interview — audience analysis, stakeholder mapping, objection preemption, cost of inaction. Claude asks ~15 questions and builds a deck engineered to move a specific buying group. Use this for strategic accounts or late-stage deals.

Day to day

Two core workflows

Building a new customer deck

  1. Open Claude Code in ~/claude/decktools
  2. Run /decktools new
  3. Answer 6 questions (Claude handles the rest)
  4. Open the generated HTML file in Chrome — no build step
  5. Iterate with plain English: "make the hero copy more direct"
  6. Share the file or host it — it's self-contained

Editing an existing deck

  1. Open Claude Code in ~/claude/decktools
  2. Say: "edit mybrand.html — change the proof section"
  3. Claude loads all style rules automatically before touching the file
  4. Review the change in Chrome, iterate
Async review

The feedback widget

How it works — reviewer side

Every deck built with decktools has a floating review button (bottom-left). Share the deck URL with a teammate — they open it in Chrome and leave comments directly on each slide. No Slack thread of disconnected feedback. No screen share required.

1
Click the chat icon bottom-left to open the review panel
2
Enter your name once — it's remembered for the session
3
Navigate slides, type comments — each one is tagged to the slide automatically
4
On first comment, Chrome asks permission to save feedback.md to your local folder — grant it once
5
Click "End Review" — saves the final file and shows a summary

Applying feedback — author side

After the reviewer sends you their feedback.md, drop it in the decktools directory and tell Claude:

read feedback.md and apply the changes to mybrand.html

Claude reads the per-slide comment threads and applies each change — copy edits, layout changes, and design notes — then reports back what it did.

Presenter mode: click the screen/play icon (bottom-right) to hide the review widget entirely during a live demo. Click again to restore review mode.

Staying current

Updates

Auto-update prompts

When the decktools skill is updated, Claude will tell you at the start of your next session:

Run claude skills install github.com/mtoolin_sfemu/decktools to update.

Run that command any time to pull the latest brand rules, components, and widget improvements. Your deck files are untouched — only the skill and shared CSS/JS files update.
