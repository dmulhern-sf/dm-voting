What you get

Three things that work together

Design System

Tokens, components, fonts, icons, and brand rules — all correct, all ready. Drop them into any deck with two `<link>` tags.

Claude Skill

Installs into Claude Code with one command. Automatically loads every brand rule before touching any deck — you never have to describe the system manually.

Before you start

Prerequisites

  • 1
    Claude Code CLI installed Install from claude.ai/code or via npm i -g @anthropic-ai/claude-code
  • 2
    Git installed Required for claude skills install to fetch the repo
  • 3
    Chrome or Edge browser Required for the feedback widget's file-write feature. Firefox works for presenting but can't write feedback.md directly.
Installation

Get up and running in 3 steps

1

Install the Claude skill

Run this once. It pulls the full decktools repo and registers the skill globally in Claude Code.

claude skills install github.com/mtoolin/sf-decktools
2

Open Claude Code in the decktools directory

All deck files live here. Claude reads the design system files from this directory automatically when the skill is active.

cd ~/claude/decktools && claude
3

Build your first deck

Type this in Claude Code. The skill kicks in automatically — it loads every brand rule, reads the canonical template, and scaffolds a new deck for your customer.

/sf-decktools new

Claude will ask: customer name, brand color, story arc, KPI numbers, and two beachhead use cases. Answer those — it builds the full deck.

What's in the repo

Key files

File What it does Use it
tokens.css All design tokens — colors, spacing, typography, gradients. Source of truth for the 2026 Salesforce brand palette. Required
components.css Every reusable component class — nav, hero, cards, proof stats, closing. Never write custom layout CSS when a component exists here. Required
sf-composer.html The canonical 12-slide best-deck example. Read this before building anything — it's the reference for structure, animation, and copy style. Required
feedback-widget.js Async review widget. Drop one script tag into any deck — reviewer leaves per-slide comments, Claude reads feedback.md to apply changes. Required

STYLE-GUIDE.md Full brand rules, voice guidelines, color system, persuasion framework (Bowden). Claude reads this automatically when the skill is active. Reference
SLIDE-PRINCIPLES.md Slide-specific rules — section order, component assignments, do/don't list. Claude reads this automatically. Reference
Day to day

Two core workflows

Building a new customer deck

  1. Open Claude Code in ~/claude/decktools
  2. Run /sf-decktools new
  3. Answer 6 questions (Claude handles the rest)
  4. Open the generated HTML file in Chrome — no build step
  5. Iterate with plain English: "make the hero copy more direct"
  6. Share the file or host it — it's self-contained

Editing an existing deck

  1. Open Claude Code in ~/claude/decktools
  2. Say: "edit westpac.html — change the proof section"
  3. Claude loads all style rules automatically before touching the file
  4. Review the change in Chrome, iterate
Async review

The feedback widget

How it works — reviewer side

Every deck built with decktools has a floating review button (bottom-right). Share the deck URL with a teammate — they open it in Chrome and leave comments directly on each slide. No Slack thread of disconnected feedback. No screen share required.

1
Click the chat icon bottom-right to open the review panel
2
Enter your name once — it's remembered for the session
3
Navigate slides, type comments — each one is tagged to the slide automatically
4
On first comment, Chrome asks permission to save feedback.md to your local folder — grant it once
5
Click "End Review" — saves the final file and shows a summary

Applying feedback — author side

After the reviewer sends you their feedback.md, drop it in the decktools directory and tell Claude:

read feedback.md and apply the changes to westpac.html

Claude reads the per-slide comment threads and applies each change — copy edits, layout changes, and design notes — then reports back what it did.

Presenter mode: click the P button (bottom-right, next to the review icon) to hide the widget entirely during a live demo. Click again to restore review mode.

Staying current

Updates

Auto-update prompts

When the decktools skill is updated, Claude will tell you at the start of your next session:

sf-decktools skill v1.1 is available.
Run claude skills install github.com/mtoolin/sf-decktools to update.

Run that command any time to pull the latest brand rules, components, and widget improvements. Your deck files are untouched — only the skill and shared CSS/JS files update.
